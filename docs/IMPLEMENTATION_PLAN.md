# Eureka Car Solution: Implementation Plan

Source brief: [`docs/EUREKA_FRONTEND_PROMPT.md`](./EUREKA_FRONTEND_PROMPT.md). This file is the build memory across sessions: tick tasks as they finish, and add notes under **Log** at the end of each phase.

## Starting state (Phase 0 inspection, 2026-11-11)

- The repo held only `docs/EUREKA_FRONTEND_PROMPT.md` and `reference/eureka-reference.html` (a 68 KB single-file Three.js r128 scroll demo with 7 chapters, a procedural "Eureka One" car, a mirror floor, a light-bar intro, paint swatches, an exploded view and a `.glb` drop-in loader). There was no `package.json`, no git and no existing code, so nothing could conflict with the brief.
- Scaffolded with `create-next-app@latest`: Next.js 16.4.6 (App Router, Turbopack), React 19.3, Tailwind CSS 4.3 (CSS-first, `@tailwindcss/turbopack` loader), TypeScript 5 (`strict`), ESLint 9 flat config with `eslint-config-next`, `src/` directory and the `@/*` alias.
- The scaffold enables `cacheComponents: true` and `partialPrefetching: true` by default, and writes an `AGENTS.md` (regenerated by `next dev`) that points at the bundled Next 16 docs in `node_modules/next/dist/docs/`.
- Node 26.9, npm 11.19. Git initialised on `main`.

## Key decisions

| # | Decision | Why |
|---|---|---|
| D1 | Keep the versions `create-next-app` chose (TS 5, ESLint 9), and add other libraries at their latest stable versions: motion, three/R3F 9/drei 10, next-intl 4, zustand 5, RHF 7 + Zod 4 + resolvers 5, Recharts 3, lucide-react, Vitest 5, Playwright 1.65. | TypeScript 7 (the native port) and ESLint 10 are the npm `latest` tags, but the Next toolchain pins TS 5 / ESLint 9. Mixing majors would break `next build` or the lint config. R3F 9 needs React < 19.4; we have 19.3. |
| D2 | Keep `cacheComponents` + `partialPrefetching`. Use `[locale]` as the single root param with `generateStaticParams` for `en`/`bn`, call `setRequestLocale` in each layout/page, and wrap `searchParams`-dependent UI (marketplace, compare, confirmation pages) in `<Suspense>`. | It's the framework default and gives a static shell with streamed dynamic parts. **Fallback:** if next-intl and Cache Components conflict at build time, set `cacheComponents: false` and record it here. |
| D3 | Locale negotiation lives in `src/proxy.ts` (Next 16 renamed `middleware` to `proxy`) using next-intl's `createMiddleware`. | Next 16 convention. |
| D4 | There's no root `app/layout.tsx`; the root layout is `app/[locale]/layout.tsx` and renders `<html lang>`. `not-found` for unmatched URLs is handled by `app/[locale]/[...rest]/page.tsx` calling `notFound()`. | It's the standard next-intl pattern, and it gives a correct `lang` per locale. |
| D5 | The mock service layer (`src/lib/api/*`) is the only importer of `src/data/mock/*`. It's enforced by an ESLint `no-restricted-imports` rule for `components/` and `app/`. | Rule 6.3, and it keeps the API swap to one folder. |
| D6 | Demo records (bookings, inquiries, applications, profile edits, demo session, document checklist) live in Zustand `persist` stores. The dashboard merges seeded demo data with session records **client-side**. | There's no server. The UI labels this "Saved in this browser only (demo)". |
| D7 | Money is integer BDT (taka); maths stays unrounded, and rounding happens only in formatters. Lakh/crore grouping uses `Intl.NumberFormat('en-IN')` for `en` and `bn-BD` for Bangla digits. | Section 6.4 / 10.G. |
| D8 | Vehicle images use an SVG silhouette placeholder per body type (no external images). `next/image` is used only when `Media.src` exists. | Rule 4. |
| D9 | *(Superseded by D30–D33.)* The 3D hero is an R3F port of the reference, condensed to 4 chapters, lazy-loaded after the HTML hero and poster. | Section 11. Performance first. |
| D10 | Maps: a styled static SVG map card plus a Google Maps search URL, with no API key. The `MapCard` component interface is kept swappable. | Section 10.N. |
| D11 | **Fonts (user override, 2026-11-11): Montserrat for English, Hind Siliguri for Bangla; no other primary font.** They replace the brief's Cormorant Garamond / Inter / Noto Serif Bengali. Both load via `next/font/google`. A single `--font-body` variable is switched by `:lang(bn)`, so the language switch re-fonts the whole site. Only the active locale's font className is rendered, so English pages never preload Bangla files. On `bn` pages Latin words (EMI, SUV) fall back to Montserrat. For `bn`: no letter-spacing, no uppercase, no synthetic italics (accents use colour), and line-height 1.75 for body / 1.35 for headings. | User instruction; brief §7. |
| D13 | Contrast fixes to brief tokens (WCAG 2.2 AA): `--muted` #6c7268 → **#5a6057** (3.9:1 → 5.0:1 on sage). Brass #9c8150 is only 3.0:1 on sage, so text on light surfaces uses **`--accent-ink` #7a6236** (4.6:1), and #9c8150 stays for borders, decoration and text on dark. EV teal text is #176660 (5.1:1). The WhatsApp button uses #1f7a4d so white text passes. | Brief §13 asks to check brass-on-sage. |
| D14 | Under Cache Components, `usePathname()` suspends on routes with not-yet-known params. Pathname reads live in tiny Suspense-wrapped leaves (`components/layout/RouteAware.tsx`: `OnRouteChange`, `NavItemLink`; `LanguageSwitcher`; `FloatingWhatsApp`), so header/footer still prerender. `useSearchParams` always needs `<Suspense>`. Use `"use cache"` + `cacheLife` for time-based values in server components (e.g. footer year). | Next 16 docs: migrating-to-cache-components. |
| D15 | `Math.random()`/`Date.now()` can't run while server components prerender. Mock **reads** used by server components (`getVehicles`, `getVehicleBySlug`, …) must be deterministic: no random latency on the server, and simulated latency only in the browser. Mock **writes** (random `DEMO-` refs) only run from client components. | Next 16 sync-IO rule. |
| D16 | The reference images in `reference/*.jpeg` are third-party renders (real manufacturer cars). They're git-ignored and used **only as art direction**: no shapes, logos or images from them ship in the product. | Rule 4. |
| D17 | **Data/UI separation.** All mock data lives in `src/data/mock`. Only `src/lib/api/*` may import it, or the browser-local records store `stores/demoRecords.ts` (ESLint `no-restricted-imports`). Session-created records are written and read *by the API layer*, so swapping in a real backend means rewriting `src/lib/api/*` only. | User request (Phase 2) + brief §6.3. |
| D18 | Vehicle content model: features/safety come from a shared bilingual catalogue (`data/mock/catalogue.ts`), but the API returns them as `LocalizedText[]` as the brief specifies. Spec tables are `SpecGroup[]` of `{ key, value, unit }`: labels live in messages (`specs.*`, `units.*`), values are numbers or language-neutral strings. Tractors use `litresPerHour`, not km/L. Reconditioned cars carry `auctionGrade`, used cars `history`, new vehicles `warranty`. | One source per string; correct units per segment. |
| D19 | Marketplace defaults: sold vehicles are hidden unless `availability=sold`, but stay reachable by URL. Facets are counted with every *other* filter applied, so models depend on the brand selection. | Standard faceting. |
| D20 | Mock test hooks (documented for QA/README): a phone ending `0000` gets a server field error; search `mock:error` makes the listing fail; demo sign-in code `123456`. Slot availability is deterministic (FNV hash of showroom/date/time), with ~1 in 4 slots taken, 30-minute slots, the last slot an hour before closing, same-day slots needing an hour's notice, and a 30-day horizon. | Brief §6.3 error simulation; reproducible e2e tests. |
| D21 | Maths: money is whole BDT in data; calculations stay unrounded (EMI, schedule, running cost). Rounding happens only in `lib/format` (`formatBDT` rounds, never shows −৳0). The amortisation schedule's last row absorbs float residue, so the closing balance is exactly 0. Break-even is measured against the most expensive option to run (0 = cheaper from day one, null = never). | User request: calculation accuracy. |
| D22 | Vehicle detail pages await `params` inside `<Suspense>` (the Next 16 Partial Prefetching pattern): all 60 locale/slug pages are fully prerendered, and client navigation shows the shell instantly. Unknown slugs get the shell, then the vehicle not-found UI with `noindex` and a not-found title. The status is 200 by framework design, and `dynamicParams` isn't available with Cache Components. | Next 16 docs: ISR with Cache Components. |
| D23 | Marketplace navigation: one `ListingStateProvider` pushes URL changes inside transitions with `useOptimistic`, so rapid clicks compose and results dim while pending. Sliders commit 450 ms after they settle; search commits on submit; any filter change resets the page to 1. | URL is the source of truth (brief §10.B). |
| D24 | Compare: `?ids=` is authoritative and the store mirrors it (opening a shared link adopts it into this browser's list). "Highlight differences" hides identical rows and marks the best value with a visible "Best" label (not colour alone). EMI and running costs in the table use shared, editable assumptions. The compare tray publishes its height as `--compare-tray-h`, so page padding and the floating WhatsApp button always clear it. On phones it starts collapsed. | Brief §10.F, §9.5. |
| D25 | Shared building blocks are built once, where first needed: `EmiCalculator` and `RunningCostCalculator` (embedded on detail pages now; Phase 4 extends them), `InquiryForm` (drawer now; the `/inquiry` page in Phase 5), `ShowroomCard` (Phase 5 adds open-now), `Segmented`, `SliderField`, `applyApiError`. Tractors get a per-working-hour cost calculator. | No duplicate components. |
| D26 | Chart colours (`lib/chartColors.ts`) come from the brand hue families with chroma raised until the dataviz validator passed every check on the ivory surface. Categorical order is teal (EV), brass, blue, terracotta, violet. The two-series pair is blue/brass (principal vs interest; energy vs maintenance). Colour follows the entity (the savings column), never rank. Legends always use text tokens, and the result tables double as the accessible table view. Recharts loads only via `next/dynamic` on the finance and savings pages. | dataviz skill; performance. |
| D27 | `EmiCalculator` is split into `useLoanCalculator` + `EmiInputs` + `EmiResults`. The embedded vehicle-page version and the full `/finance` calculator (vehicle picker, conventional/Islamic terminology, donut, year→month schedule) share all state and maths. "Apply with these numbers" carries `vehicle/price/down/tenure/type` into `/finance/apply`. | One calculator, two surfaces. |

The Continue and Submit buttons have distinct React keys: reusing one element let a Continue click submit the form (found in QA). | Brief §10.G, §12. |

## 3D hero art direction (from `reference/car-image1–4.jpeg`, applied in Phase 8)

The four references share one visual language. We translate it into an original car and scene; we don't copy the referenced vehicles.

| Ref | What it shows | How Eureka uses it |
|---|---|---|
| 1. Clay roadster, exploded side view | Matte clay-white body, soft studio light, doors/panels floating above the car on their own axes, soft contact shadow, seamless white backdrop | **Base look:** matte clay material (`--clay` #eeeeea, roughness ~0.55), soft key + large area fill, contact shadow, and parts that lift away along their own axes |
| 2. X-ray chassis on concrete | Ghost body as cyan hairlines; chassis, suspension and drivetrain visible; red calipers as the only saturated accent; small tag labels | **Engineering chapter:** body fades to x-ray edges (`--xray` #8ad8cc line material) to reveal battery floor, twin motors and suspension. Red is kept for calipers/tail light only |
| 3. Graphite studio, annotated exploded view | Dark graphite backdrop, glass-transparent panels, thin white leader lines with numbers | **Callout system:** numbered hairline leader lines (HTML overlay projected from 3D anchor points) on the dark graphite chapter. The same pattern is reused in UI (mega-menu numbering, poster, spec callouts) |
| 4. Clay SUV, exploded front view on a grid cyclorama | Parts radiating outward (wheels, seats, suspension, brakes), faint grid wall | **Exploded view:** radial explode from the centre of mass with a slight stagger; faint grid cyclorama (`bg-studio-grid` in UI) |

**Chapters (~400vh, then hand off to normal sections):**
1. **Awakening** (0–25%): dark studio, the light bar draws across the nose, then studio lights rise to reveal the clay car. Headline and CTAs are in HTML.
2. **Form & finish** (25–50%): slow orbit along the shoulder; clay → paint transition (brass, onyx, sage, ivory swatches); mirror floor reflection.
3. **Engineering** (50–80%): backdrop shifts to graphite; the body turns x-ray; panels, doors, wheels and seats explode outward; the battery floor lowers; 3–4 numbered callouts.
4. **Arrival** (80–100%): parts reassemble, camera settles to a three-quarter hero, and the scene hands over to the quick-search bar.

**Fallback:** `components/home/HeroPoster.tsx` (built in Phase 1) is the static SVG of this direction and the LCP element. It's used on <768px, with reduced motion, without WebGL, or when `deviceMemory < 4`.

## Conflicts between existing code and the brief

None. The repo was empty apart from the brief and the reference demo. The only adaptations: the brief's `middleware` becomes Next 16's `proxy.ts` (D3), and Cache Components needs `Suspense` boundaries around request-dependent UI (D2).
